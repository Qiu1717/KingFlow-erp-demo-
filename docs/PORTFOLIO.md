# KingFlow ERP - 项目介绍

**项目类型**：个人作品 / 企业进销存 Web Demo  
**开发角色**：全栈开发（Codex AI 辅助）  
**开发时间**：2026年10月；V1业务阶段完成于10月16日  
**适用场景**：单企业、多仓库、中小型商贸业务；中文界面、人民币、PC浏览器。

## 项目解决的问题

将采购、仓库、销售和财务往来串成可操作、可追溯的业务闭环。页面提交真实API并持久化到SQLite，审核、入库、出库、收付款由后端业务规则控制，刷新后数据保留。

- 采购：草稿 → 提交审核 → 审核通过 → 分批入库 → 应付 → 部分/全额付款。
- 销售：草稿 → 提交审核 → 审核通过 → 分批出库 → 应收 → 部分/全额收款。
- 库存：商品与仓库独立余额、带来源的库存流水、调整原因、低库存预警。
- 分析与管理：经营概览、排行/趋势/CSV，六类角色权限、用户及审计、个人设置。

## 技术方案

2026-10-19新增「数据可视化」：按角色显示销售、采购、库存、往来四类主题，提供面积趋势、横向排行、仓库对比与环形占比、应收应付结算结构图。可切换金额/数量，按上海日期、仓库和关键词查询；图表、汇总及CSV均由同一真实报表API提供。新增截图见screenshots/07-visualizations-sales.png及08/09；PDF保留10月17日原版，增补内容见README和离线展示页。

前端：React、TypeScript、Vite、Ant Design、React Router、TanStack Query、Zustand、Axios、Recharts。  
后端：Node.js、Express、TypeScript、Prisma、SQLite、Zod、bcrypt、Session。  
工程与验证：pnpm workspace、ESLint、Vitest、Supertest、Playwright；锁文件、数据库迁移和幂等Seed随包提供。

调用链：浏览器 → API Client → Route/Controller → Service业务规则与事务 → Repository/Prisma → SQLite。

## 重点工程能力

1. **数据一致性**：出入库同时更新余额、流水、订单状态和应收应付；下游任一步失败整体回滚。
2. **并发与重复请求**：事务内写锁与条件更新避免负库存或超结；幂等键绑定用户、业务类型和请求摘要，唯一约束防重复过账。客户端网络异常保留原请求，刷新后可确认结果。
3. **金额与历史快照**：数量为整数，金额以整数分存储；订单保留商品名称、规格、单位和成交价快照，不随参考价格变化。
4. **服务端权限与输入校验**：六类默认角色，敏感API独立授权；密码哈希、HttpOnly Cookie、CSRF与来源校验、登录限流、审计脱敏及CSV公式防护。
5. **可复现的质量验证**：独立真实数据库测试覆盖并发库存/余额、事务回滚和幂等；浏览器覆盖登录、主数据、采购销售收付闭环、权限、断网恢复及账号缓存隔离。实际交付检查见VERIFICATION.md。

## 开发方式与成果边界

使用Codex辅助进行实现、调试与回归，围绕需求、业务规则、阶段验收持续迭代。作品提供完整源码与测试，便于在面试中演示、解释关键取舍与复现验证。

不宣称商业上线、真实客户数量、生产并发或未经测量的效率提升。SQLite适合本地/受控演示，报表按Demo数据规模在内存聚合；收付款是业务记录，不连接银行；不包含会计总账、税务、生产制造、退货、调拨及已过账冲销。
