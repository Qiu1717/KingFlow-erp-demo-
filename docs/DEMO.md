# 面试演示指南

## 新增可视化演示

登录后展开「经营报表」，打开「数据可视化」，依次展示销售、采购、库存和往来页签（由角色权限控制）。销售/采购切换金额与数量，选择近30天或自定义日期及仓库，悬停查看趋势或排行数值，再导出相同筛选条件的CSV。库存页展示仓库对比与占比；往来页展示已结、未结金额。完成业务过账后返回本页或使用「刷新数据」查看更新。金额按元显示，日期按上海时间，库存历史余额与当前预警口径在页面说明。

## 1. 启动（首次需安装依赖）

在解压后的项目根目录打开终端，准备Node.js 22.12+或24、pnpm 11.25。初次安装依赖需要网络；无需付费云服务。

```powershell
pnpm install --frozen-lockfile
pnpm db:migrate
pnpm db:seed
pnpm dev
```

访问 http://localhost:5173；不要直接双击apps/web/index.html。根目录“作品集展示.html”仅是离线介绍与截图，真实业务需运行API和数据库。

管理员admin，初始密码KingFlow@2026。其他账号purchase/sales/warehouse/finance/guest使用相同初始密码；只供本地演示。默认配置无需创建.env，需要自定义时参考.env.example。

## 2. 约5分钟业务演示

1. 管理员登录：查看真实经营指标、销售趋势、采购对比及待办。
2. 新建专用商品A（用唯一编码，如INTERVIEW-A），单位件，参考采购价80元、销售价120元；选择任一启用分类。
3. 采购订单：供应商和仓库选演示资料，商品A数量10、单价80，保存草稿→提交审核→审核通过。
4. 分批入库：先入6件，再入4件。对应库存0→6→10，订单部分→全部入库，产生480元与320元两笔应付及两条来源流水。
5. 销售订单：同一商品和仓库，数量3、单价120，保存→提交→审核→出库。库存10→7，应收360元。
6. 打开应收详情，先收100元，余额260、部分结清；再收260元，余额0、已结清，不能继续收款。对应应付也可以分批或全额付款。
7. 查看库存流水和报表，点击来源单据追溯；销售报表只统计正式出库。导出CSV查看中文标题和真实数据。
8. 库存调整：填写原因，试图盘亏超过余额时被拒绝；正常调整写入来源、操作者和前后数量。

注意：专用新商品保证初始库存为0，不受既有演示数据影响。请勿使用开发重置来清理他人的数据。

## 3. 展示权限和可靠性

- purchase创建和审核采购；warehouse执行出入库；finance录入收付款。管理员可完整演示，访客只读。
- sales登录访问财务专用页面/API会被拒绝；前端隐藏按钮并不能替代后端授权。
- 未审核不能出入库，出库超过订单余量或实际库存被拒绝，超额收付款被拒绝。
- 审核、过账、调整和结算具有审计记录。正式单据不允许直接修改或删除。
- 网络异常时用原键重试；自动化用真实API注入响应丢失，证明刷新后不会重复过账。不要手工篡改前端状态演示成功。

## 4. 代码讲解切入点

- apps/api/src/services/inventory-service.ts：同仓库条件扣减与流水。
- purchase-service.ts / sales-service.ts：审核状态、余量校验、事务、幂等与历史快照。
- finance-service.ts：余额条件更新、结算方向与来源、并发/重放。
- packages/shared/src：状态与Zod约束；apps/api/tests：真实库、并发与故障回滚；tests/e2e：真实浏览器。

## 5. 测试与常见启动问题

先停止开发服务，再依次执行：

```powershell
pnpm lint
pnpm typecheck
pnpm test
pnpm exec playwright install chromium
pnpm test:e2e
pnpm build
```

若本机已安装Chrome，可在PowerShell设置 `$env:PLAYWRIGHT_CHANNEL='chrome'` 后运行E2E。测试使用独立test.db/e2e.db，不修改dev.db。Windows上运行中的API会占用Prisma DLL，迁移或测试前先停止它；E2E需要3001/5173空闲。生产Cookie需要HTTPS，不能用NODE_ENV=production直接运行本地HTTP演示。
